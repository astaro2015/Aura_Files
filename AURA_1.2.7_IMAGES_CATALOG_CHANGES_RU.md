# Aura Files 1.2.7 — каталог изображений

Дата: 2026-09-07

## Что исправлено

Ранее экран «Изображения» получал до 5000 последних файлов, затем группировал их по источнику и выводил группы в порядке «Камера», «Загрузки», WhatsApp, Telegram, «Снимки экрана» и т. д. Если в Camera было много фотографий, пользователь сначала видел почти только Camera, а старые изображения за пределами лимита 5000 вообще не могли появиться.

В 1.2.7 раздел «Изображения» переведён на отдельную индексную выборку:

- по умолчанию показываются все изображения по дате изменения, новые сверху;
- сверху добавлены быстрые фильтры: `Все`, `Камера`, `Снимки экрана`, `WhatsApp`, `Telegram`, `Загрузки`, `Другие`;
- фильтр работает прямо по `sourceFolder` полного Room-индекса, поэтому «Снимки экрана» не зависят от количества фотографий Camera;
- прежний жёсткий потолок 5000 для экрана «Изображения» удалён;
- данные загружаются страницами по 400 объектов; если есть следующая страница, внизу появляется `Показать ещё` с количеством уже загруженных и общим количеством;
- поиск имени выполняется в SQL по всей выбранной подкатегории, а не только по уже загруженной странице;
- сортировка имени/даты/размера/типа также выполняется в индексной SQL-выборке, поэтому порядок остаётся корректным между страницами;
- при смене фильтра, поиска, сортировки или настроек видимости текущая страница безопасно перезагружается;
- уход с экрана отменяет незавершённую загрузку коллекции;
- фоновой warm-cache больше не пытается заранее загружать всю категорию изображений.

## Классификация скриншотов

Используется существующая классификация `FileClassifier`: каталоги `Pictures/Screenshots`, `DCIM/Screenshots`, `Screenshot` и аналогичные пути попадают в `Снимки экрана`. Добавлен регрессионный unit-test для распространённых Android-путей.

## Что не менялось

- физические файлы не перемещаются и не дублируются;
- категория `Камера` на главном экране не меняла семантику;
- облачные backend'ы, OAuth Яндекс.Диска/Google Drive и cloud UI 1.2.6 не изменялись;
- схема Room не изменена: добавлены только DAO-запросы, миграция БД не требуется.
