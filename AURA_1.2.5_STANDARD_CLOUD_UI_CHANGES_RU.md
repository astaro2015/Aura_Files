# Aura Files 1.2.5 — стандартный интерфейс облака

Дата: 2026-09-07

## Задача
Сделать Яндекс.Диск визуально и по управлению частью обычного файлового интерфейса Aura, не подменяя облачные операции локальными `DocumentFile`/`Uri` и не оставляя неработающих кнопок.

## Что изменено
- Однопанельное облако теперь открывается через `StandardBackendBrowser` в `BackendWorkspaceActivity`.
- Повторно используются общие элементы Aura: `BrowserHeader`, `BrowserControls`, `AuraSearchField`, `EmptyFolder`, `NameDialog`.
- Добавлены стандартные list/grid представления для `StorageItem`, выделение и нижняя панель действий.
- Добавлен облачный clipboard: `Копировать` / `Переместить` / `Вставить` работают через существующий `BackendTransferCore`.
- Перемещение внутри одного backend использует `backend.move()`; для Яндекс.Диска это серверное move API.
- Копирование использует безопасный transfer-core с временной записью, конфликтами имён и прогрессом.
- Создание папки, переименование, свойства, открытие/скачивание и удаление остаются backend-операциями.
- Для Яндекс.Диска подтверждение удаления прямо сообщает, что объект отправится в корзину Яндекс.Диска (`permanently=false`).
- Исправлён текст подтверждения удаления и в старом dual-pane UI.

## Что намеренно НЕ показывается в облачном браузере
Пока backend не имеет корректной реализации, не показываются локальные действия:
- Избранное;
- изменение даты файла;
- архивировать / распаковать;
- системный звук;
- локальные миниатюры/операции, завязанные на Android `Uri`;
- локальная корзина Aura.

Это сделано специально: стандартный интерфейс должен показывать только реально работающие функции.

## Двухпанельный режим
Кнопка двух панелей сохранена. Это отдельный инструмент для переноса между локальным, SMB/FTP/SFTP и облачными backend'ами. Однопанельный режим предназначен для обычного просмотра и работы внутри подключённого хранилища.
