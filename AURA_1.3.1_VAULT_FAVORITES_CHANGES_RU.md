# Aura Files 1.3.1 — защищённое «Избранное»

## Что изменено

Прежнее «Избранное» было списком URI-ссылок и никак не скрывало исходные файлы. В 1.3.1 оно заменено на зашифрованный сейф Aura.

### Хранение

Физический каталог: `/storage/emulated/0/.AuraVault/data/` (корень общей памяти текущего пользователя Android).

Внешние имена исходных файлов не сохраняются. Каждый объект хранится как случайный UUID `.avf`; метаданные и содержимое зашифрованы. В `.AuraVault` создаётся `.nomedia`.

### Ключ

Никакого PIN, биометрии, master-key файла или `vault.key` нет.

Схема:

`ANDROID_ID → HKDF-SHA256(info="AuraVault-v1") → 256-bit AES key`

HKDF используется с пустой/нулевой солью по стандартной схеме Extract+Expand. Файлы шифруются AES/GCM/NoPadding; metadata и data имеют отдельные случайные 96-bit IV, а metadata ciphertext привязан к data как AAD.

Практическое следствие: обычная переустановка той же Aura с той же подписью на том же устройстве/Android user должна снова вывести тот же ключ. Перенос `.AuraVault` на другой телефон даёт другой `ANDROID_ID`, поэтому штатная Aura там не расшифрует контейнер.

Это не парольная защита от специалиста, способного получить идентификаторы исходного устройства и реверсить APK. Это device-bound privacy vault без действий пользователя.

### Добавление

«В избранное» теперь означает только **переместить**:

1. Aura пишет временный зашифрованный `.avf`.
2. fsync/закрытие контейнера завершаются до удаления исходника.
3. Контейнер переименовывается в постоянный UUID.
4. Только после этого удаляется исходный DocumentFile.
5. Если удалить исходник не удалось, новая vault-копия удаляется и операция считается отменённой.
6. При любой ошибке до завершения move временный и постоянный vault-контейнеры откатываются; валидная вторая копия не должна оставаться после неудачного перемещения.

Папки в 1.3.1 не поддерживаются: UI отключает «В избранное» для выделения, содержащего директории.

### Просмотр / возврат

Плитка на главной остаётся «Избранное». Она открывает `VaultActivity`.

Внутри доступны:
- обычный тап — временная расшифровка в private cache Aura и ACTION_VIEW;
- «Поделиться» — временная расшифровка + FileProvider;
- «Вернуть» — системный выбор обычной папки, расшифровка туда и удаление `.avf` только после успешной записи;
- «Удалить» — безвозвратное удаление зашифрованного объекта с подтверждением.

Временные plaintext-копии лежат только во внутреннем cache Aura и чистятся по возрасту при каждом открытии/обновлении сейфа и перед созданием новой временной копии.

При расшифровке AES-GCM тег проверяется явным `Cipher.doFinal()`. Если контейнер повреждён или ключ не подходит, операция считается ошибочной, а частично записанный plaintext удаляется вызывающей операцией.

### Скрытие служебного каталога

`.AuraVault` всегда исключён из обычного `FileRepository.listChildren()` и из полного `StorageIndexer.scan()`, независимо от настройки «Показывать скрытые». Поэтому `.avf` не попадают в категории, дубликаты, недавние и карту памяти Aura.

## Ограничения

- Для создания/чтения persistent vault нужен режим Aura «Весь накопитель».
- Factory reset, другой Android user или смена signing key Aura могут изменить app-scoped `ANDROID_ID`; старый vault тогда автоматически не откроется.
- Удаление `.AuraVault` сторонним файловым менеджером удаляет сейф физически.
