Проверено по актуальной документации Яндекса:
- device-code: POST https://oauth.yandex.ru/device/code;
- token exchange: POST https://oauth.yandex.ru/token, grant_type=device_code;
- refresh: POST https://oauth.yandex.ru/token, grant_type=refresh_token;
- refresh может вернуть новый refresh token, который требуется сохранять;
- проверка Disk token: GET https://cloud-api.yandex.net/v1/disk/ с Authorization: OAuth <token>.

Дополнительные защитные решения:
- новый аккаунт сохраняется только после успешного Disk API info запроса;
- access+refresh token rotation сохраняется через защищённый CloudTokenStore этапа 1;
- при отсутствии нового refresh token сохраняется предыдущий;
- refresh accessToken синхронизирован, чтобы параллельные операции не обновляли один refresh token одновременно;
- OAuth request body, Authorization header и OAuth response body не печатаются в toString;
- access token / refresh token / client secret / device_code редактируются в строковом представлении моделей.
