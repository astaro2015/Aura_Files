Aura Files 1.2.1 CLOUD AUTH FIX — проверка пакета
Дата: 2026-09-06

Цель исправления
- Реальный Android-тест 1.2.0 показал сброс Yandex device-code flow после браузера.
- После Google AuthorizationClient flow пользователь видел две локальные панели вместо Google Drive.

Исправления Yandex
- Device-code protocol повторно сверён с актуальной документацией Яндекс OAuth:
  POST /token, grant_type=device_code, code=<device_code>.
- Pending login сохраняется через SavedStateHandle: clientId/deviceCode/userCode/verificationUrl/interval/expiry.
- После Activity/process recreation восстанавливается тот же pending flow и продолжается polling.
- Восстановленный flow не переоткрывает браузер автоматически.
- Pending state очищается при успехе, отмене, expiry/error.
- После успеха Yandex backend регистрируется и выбирается в панели атомарно.

Исправления Google Drive
- Незавершённый AuthorizationClient flow помечается в SavedStateHandle.
- ActivityResult после пересоздания Activity/ViewModel больше не теряется.
- После успеха Google backend регистрируется и сразу выбирается в левой/верхней панели; локальный backend — во второй.
- Добавлен process-only GoogleAccessTokenMemoryCache для первого открытия Drive после интерактивного OAuth.
- Google token cache не пишется на диск, очищается при invalidate/revoke и исчезает с процессом.
- Backend registration/selection после OAuth проверяется явным invariant-check.

AndroidX lifecycle API
- Добавлена явная зависимость lifecycle-viewmodel-savedstate:2.10.0.
- SavedStateHandle get/set/remove и SavedStateViewModelFactory(Application, SavedStateRegistryOwner) сверены с актуальным AndroidX API.
