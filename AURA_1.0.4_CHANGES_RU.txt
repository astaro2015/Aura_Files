Aura Files 1.0.4 — SMB reliability and safety audit

База: официальный GitHub Aura Files 1.0, commit 63773f432aa700d042b57b8f98ad3091e209ea4d, плюс исправления 1.0.1–1.0.3.

SMB-аудит и исправления:
- обнаруженное SMB-устройство открывает форму подключения вместо неявной попытки Guest;
- введённые SMB-учётные данные никогда не откатываются автоматически на Guest/Anonymous;
- Guest/Anonymous используются только при пустом имени пользователя; старые пароль и домен в guest-профиле не сохраняются;
- поддержаны и нормализуются server, \\server\share, smb://server/share, server:445 и [IPv6]:445/share; нестандартный SMB-порт отклоняется явно;
- DOMAIN\user и user@domain приводятся к единой форме; конфликт отдельно введённого домена определяется до подключения;
- ошибки SMBJ/jCIFS преобразуются в пользовательские сообщения без внутренних адресов вида 0.0.0.0<00>/...;
- сохранённый SMB-профиль получает стабильный ID; домен участвует в идентичности; дубли профилей не конфликтуют в StorageBackendRegistry;
- профиль сохраняется только после успешного соединения, выбранная шара сохраняется после выбора; возврат к списку шар не стирает сохранённую шару;
- удаление активного SMB-профиля закрывает его соединение перед удалением секрета;
- безопасные list/stat/open-read повторяются один раз только после транспортного обрыва; ACCESS_DENIED/NOT_FOUND и другие смысловые ошибки не маскируются reconnect-ом;
- операции записи, rename/move/delete не повторяются автоматически после обрыва, поскольку состояние commit может быть неизвестно;
- после transport failure повреждённая SMB-сессия закрывается, следующая команда начинает новое соединение;
- основной SMB upload больше не создаёт временный файл с атрибутом Hidden; используются обычные .aura-part-*;
- destination path при upload берётся из TransferRequest, а не из изменяемого currentPath репозитория;
- скачиваемый локальный файл получает MIME по конечному имени, а не всегда application/octet-stream;
- прогресс SMB-передач связан с общими Pause/Resume/Cancel; быстрый повторный запуск не может перетереть controller другой операции;
- навигация/refresh/disconnect блокируются на время конфликтующей SMB-операции;
- reparse-point/junction отмечаются в SmbEntry/StorageItem и не обходятся рекурсивно; перед recursive copy/download/delete серверные атрибуты перечитываются заново; если безопасную проверку выполнить нельзя, операция прекращается;
- при recursive delete в универсальном SMB backend junction удаляется как ссылка без обхода её цели;
- сравнение имён учитывает case-sensitive Samba и case-insensitive Windows/NAS без ложного совпадения только по регистру;
- временные .aura-part-* и .aura-dir-* удаляются при отмене/ошибке по возможности;
- добавлены regression-тесты нормализации SMB target/identity, сообщений ошибок, определения transport failures и transfer safety для link-like backend objects.

SMB1 намеренно не включён; поддерживаются SMB2/SMB3. OCR намеренно не включён.
