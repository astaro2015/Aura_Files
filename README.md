## История: Aura Files 1.3.15

## System MediaStore APK share handoff (1.3.15)

На Android 10+ готовый APK перед отправкой публикуется в системный `MediaStore.Downloads` на `VOLUME_EXTERNAL_PRIMARY` (`Загрузки/Aura Files`) и только после проверки передаётся через обычный Android Sharesheet. Messenger-facing MIME фиксирован как `application/octet-stream`; `ClipData.newRawUri()` не даёт provider MIME повторно превратить вложение в APK MIME. Получатель не закрепляется через `setPackage`/`setComponent`. Если OEM ломает MediaStore, используется preflight-проверенный native Aura ContentProvider fallback.

## Native share provider fix (1.3.14)

Реальный тест 1.3.13 показал, что проблема была глубже: outgoing URI уже строился самой Aura, но обслуживал его всё ещё AndroidX `FileProvider`, и `ContentResolver.openFileDescriptor()` снова падал на `Missing android.support.FILE_PROVIDER_PATHS meta-data`. В 1.3.14 AndroidX FileProvider полностью удалён из share-path: Aura использует собственный read-only `ContentProvider`, который сам безопасно сопоставляет `content://` URI с разрешёнными файлами. Manifest meta-data и `file_paths.xml` больше не участвуют вообще.

Файловый менеджер для Android с лаконичным интерфейсом в духе Apple. Основное приложение написано на Kotlin и Jetpack Compose; встроенные движки чтения книг используют Java.

## FileProvider URI generation fix (1.3.12)

После реального теста 1.3.11 выяснилось, что subclass `AuraFileProvider(R.xml.file_paths)` сам по себе недостаточен: статический AndroidX `FileProvider.getUriForFile()` всё равно заново читает `FILE_PROVIDER_PATHS` через PackageManager. В 1.3.12 outgoing URI формируется самой Aura через `AuraFileProvider.uriForFile()` с канонической проверкой разрешённых roots. Все production-вызовы статического URI generator удалены; provider продолжает обслуживать URI через `FileProvider(R.xml.file_paths)`.


## FileProvider OEM fix (1.3.11)

На тестовом Xiaomi после нажатия «Поделиться» Aura доходила до `FileProvider.getUriForFile()`, но прошивка возвращала `Missing android.support.FILE_PROVIDER_PATHS meta-data`, несмотря на наличие meta-data в исходном manifest. Прямое объявление `androidx.core.content.FileProvider` заменено собственным `AuraFileProvider : FileProvider(R.xml.file_paths)`. Пути теперь закреплены в конструкторе provider; manifest meta-data сохранена как совместимый fallback.

## Исправление «Поделиться APK» (1.3.10)

На Xiaomi/MIUI системный chooser мог не появляться даже после успешного поиска внешнего receiver. Теперь Aura сначала закрывает «APK готов», затем через `window.decorView.post` показывает собственный список внешних ACTION_SEND targets и запускает выбранный exact `ComponentName` с явным FileProvider read grant. MIME priority: `application/octet-stream` → `*/*` → APK MIME.

## Исправление «Поделиться APK» (1.3.9)

- После успешной сборки единого APK Aura больше не запускает системный chooser вслепую только с `application/vnd.android.package-archive`.
- Перед запуском проверяется наличие внешнего приложения-получателя. MIME выбирается по цепочке: APK MIME → `application/octet-stream` → `*/*`.
- Это исправляет сценарий Xiaomi/MIUI, где кнопка «Поделиться» могла закрыть диалог и оставить пользователя в Aura без системного списка приложений.
- `FileProvider`, `ClipData` и временное read-разрешение сохраняются; если внешнего получателя действительно нет, Aura показывает явное сообщение вместо молчаливого возврата.
- Merge/sign/verify pipeline 1.3.8 не изменён.


## Единый APK из SPLIT (1.3.6)

- В `Очистка → Приложения` для SPLIT-приложения основное действие теперь **«Поделиться APK…»**: Aura объединяет установленный `base.apk + splitSourceDirs` в один APK.
- Слияние ресурсов и manifest основано на APKEditor 1.4.9 / ARSCLib 1.4.0; split-required markers и старая подпись удаляются до финальной подписи.
- Получившийся APK подписывается отдельной локальной software RSA identity `Aura APK Export` в `noBackupFilesDir`, затем повторно проверяются подпись, package name и versionCode. Ключ подписи самой Aura для экспорта чужих APK не используется.
- Начиная с 1.3.7 legacy v1/JAR signing отключён: Aura задаёт signing floor API 26 и использует v2/v3, что соответствует минимальной версии самой Aura и убирает проблемный on-device PKCS#7 path.
- Поскольку исходная подпись разработчика после merge недоступна, единый APK предназначен для чистой установки либо обновления APK, ранее экспортированного той же установкой Aura. Поверх Play/оригинальной версии с другой подписью Android его не установит.
- Кнопка **APKS** сохранена рядом как fallback для защищённых/нестандартных приложений или случаев, когда merge невозможен.
- `.apks` installer/export остаётся полностью поддержан и не удалён.


## Android runtime signer (1.3.8)

- Host-oriented `com.android.tools.build:apksig` удалён из runtime dependencies: upstream AOSP прямо позиционирует его как инструмент для использования вне Android-устройств.
- На устройстве используется `MuntashirAkon/apksig-android 4.4.0`, сохраняющий публичный API `com.android.apksig.*`, но адаптированный для Android runtime.
- JitPack ограничен группой `com.github.MuntashirAkon`, чтобы не менять источник остальных зависимостей.
- Signing floor остаётся API 26: v1/JAR отключён, v2+v3 включены.
- v4 явно отключён: он создаёт отдельный `.idsig` sidecar и не нужен для экспорта одного самостоятельного APK.
- Проверка подписи, package name/versionCode, atomic publish и APKS fallback сохранены.

## Hotfix подписи Universal APK (1.3.7)

- Исправлен runtime-сбой `SignatureException: Failed to sign` после merge.
- Реализация 1.3.6 ошибочно принудительно включала v1/JAR signing, хотя design функции требовал v2+v3 для API 26+.
- Теперь signer и verifier явно используют нижнюю границу API 26; v1 отключён, v2/v3 включены.
- Audit harness закрепляет это как регрессионный инвариант.

## Глубокий safety/release audit (1.3.5)

- Сетевые и облачные операции hardened против lost ACK, stale ID/session, неоднозначного MOVE/DELETE/REPLACE и ошибочного destructive fallback.
- Пакетное переименование получило durable crash journal и восстановление после process kill; локальный REPLACE и Vault Restore получили собственные crash-safe журналы.
- Восстановлены потерянные safety-защиты рекурсивных локальных операций и корзины: depth/cycle/symlink guards, orphan trash recovery и conservative ambiguous-delete policy.
- Viewer/reader/cache paths hardened против EXIF inconsistency, OOM, зависших jobs, частичных preview/plaintext-файлов и переполнения внутреннего cache.
- APK/APKS import/export/install hardened: size/space limits, cooperative cancellation, atomic temp commit и доверенный PackageInstaller callback по session+nonce.
- Dependency audit обновил XZ for Java до 1.12 и Bouncy Castle до 1.85.2; third-party notice приведён к фактическим runtime dependencies.
- Финальный clean Android build выполняется `BUILD_ON_CLEAN_WINDOWS.bat`; контейнерный audit не подменяет его статическими проверками.




## «Все» на главной (1.3.4)

- На главной плитка «Другие» заменена на **«Все»** — это не фильтр индекса, а прямой вход в корень общей внутренней памяти.
- Если системное разрешение «Управление всеми файлами» уже выдано, плитка сразу открывает стандартный локальный файловый браузер Aura со всеми папками и файлами.
- Если полного доступа ещё нет, плитка показывает «Нужен полный доступ» и открывает системную страницу выдачи разрешения; после возврата Aura подключает корень автоматически.
- `.AuraVault` и служебная корзина Aura по-прежнему исключены из обычного просмотра. Съёмные/USB-накопители остаются отдельными пунктами в «Подключённых накопителях».
- Плитка **«Книги»** содержит EPUB/FB2/MOBI/AZW/CBZ/CBR; PDF/DOCX/TXT и другие документные форматы остаются в «Документах».

## Единый SMB-браузер (1.3.3)

- Страница `Сеть` больше не встраивает удалённый список SMB-файлов после карточек подключений/серверов.
- Сохранённый SMB-профиль с выбранной шарой открывается сразу в стандартном однопанельном `BackendWorkspaceActivity`, как Яндекс.Диск/Google Drive.
- Для нового SMB без указанной шары `Сеть` показывает модальное окно выбора общей папки; после выбора профиль сохраняется и файловый браузер открывается автоматически.
- В SMB-браузере используются общий UX Aura: назад, breadcrumbs, обновление, две панели, создание папки, поиск, сортировка, список/плитка, выделение, копирование/перемещение/вставка, переименование, свойства и удаление. Реальные операции остаются через `SmbStorageBackend`.
- Старый `SmbRepository` на главном экране оставлен только для авторизации/обнаружения шар и после передачи управления backend-браузеру тихо освобождает соединение.


## Защищённое «Избранное» (1.3.2)

- Старые URI-закладки заменены настоящим зашифрованным хранилищем `.AuraVault` в общей памяти устройства.
- При команде «В избранное» файл **перемещается**: сначала полностью шифруется, и только затем удаляется исходник. Режима копирования нет. С 1.3.2 большие файлы пишутся в AVF2 независимыми AES-GCM блоками по 1 MiB, поэтому шифрование не требует RAM размером со весь файл.
- Ключ нигде не хранится: `ANDROID_ID → HKDF-SHA256(info="AuraVault-v1") → AES-256-GCM`. Для каждого объекта используются случайные GCM IV.
- Имена, MIME/размер/дата и содержимое файлов зашифрованы; на диске видны только UUID-файлы `.avf`, а `.nomedia` не даёт медиасканеру трогать сейф.
- После обычного удаления/переустановки Aura на том же Android-пользователе и с той же подписью приложения ключ вычисляется снова; копия `.AuraVault` на другом телефоне не открывается. Factory reset/другой Android user/другая подпись Aura могут изменить `ANDROID_ID` и сделать старый сейф недоступным.
- Из «Избранного» файл можно открыть, посмотреть/запустить штатными viewer/player/reader/APK/APKS экранами Aura, поделиться им через временную приватную расшифровку или **«Вернуть»** в выбранную обычную папку. Для новых image/video миниатюра хранится внутри AVF2 в зашифрованном виде.
- `.AuraVault` исключён из обычного браузера Aura, StorageIndexer, локального backend и встроенных FTP/SFTP listings, чтобы служебные `.avf` не попадали в категории/анализ и не раздавались сетевыми серверами Aura.
- Папки в 1.3.2 намеренно не принимаются в сейф: пункт «В избранное» для выбранных папок отключён.

## Передача приложений / SPLIT installer (1.3.0)

- В `Очистка → Приложения` сохраняются иконки, версии, package name и метки `APK` / `SPLIT · N APK`.
- Обычный APK по-прежнему можно сразу отправить через системное «Поделиться…».
- SPLIT теперь экспортируется целиком: `base.apk + splitSourceDirs` собираются в один Aura `.apks`.
- `.apks` содержит manifest с package/version/device metadata, размерами и SHA-256 всех APK.
- На другом телефоне Aura открывает один `.apks`, проверяет комплект и устанавливает все его APK одной `PackageInstaller.Session`.
- Если Telegram/Android не предложил открыть `.apks` в Aura напрямую, есть явный fallback: `Очистка → Приложения → Установить .APKS` → системный выбор файла.
- Поддержаны штатное разрешение unknown sources, системное подтверждение установки и понятные PackageInstaller statuses.
- Это device-specific перенос установленного набора, а не восстановление universal APK; данные/OBB/отдельные Play Asset Delivery packs не экспортируются.

## Облачный браузер (1.2.5)

Облачные операции при этом остаются через `StorageBackend`, а локальные функции, для которых у облака нет корректной реализации, не показываются. Для переноса между локальным/сетевым/облачным хранилищами сохранён отдельный двухпанельный режим.

Анализ запускается только вручную, читает только подключённую пользователем область и не удаляет файлы автоматически. Жёсткого предела в 10 000 файлов больше нет: индекс записывается в Room пакетами, а интерфейс получает ограниченные выборки по запросу.

На Android 11 и новее полный режим нужно отдельно включить в системных настройках по кнопке «Весь накопитель». Даже это разрешение не обходит защиту чужих каталогов `Android/data` и не предоставляет системный root-доступ `/`.

Пароли FTP/SMB/SFTP и приватные SSH-ключи хранятся через защищённое хранилище на базе Android Keystore. OAuth-токены Яндекс.Диска хранятся отдельно в AES-GCM-хранилище, привязанном к Android Keystore. Google Drive использует Google Identity Services: Aura не сохраняет Google refresh-token и получает текущий access token через Google Play services. Обычный FTP не шифрует данные в сети; для защищённого сервера включите FTPS (TLS) в настройках подключения. После глубокой приостановки приложения Android может закрыть сетевой сокет — Aura проверяет соединение и автоматически выполняет повторный вход перед следующей операцией.

Встроенный FTP-сервер принимает подключения только из локальной сети. Он использует обычный незашифрованный FTP, поэтому включайте его только в доверенной домашней сети и останавливайте после передачи файлов. По умолчанию сервер запускается в режиме «только чтение».

## Сборка

Требования: JDK 17, Android SDK 36, Build Tools 36.0.0 и Android NDK 28.2.13676358.

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug lintDebug assembleRelease
```

Готовый отладочный APK создаётся в `app/build/outputs/apk/debug/app-debug.apk`, а компактный оптимизированный APK — в `app/build/outputs/apk/release/app-release.apk`.

На Windows Android Gradle Plugin предупреждает о путях с кириллицей. Проект включает `android.overridePathCheck=true`, но для максимально предсказуемого запуска тестов рекомендуется каталог с ASCII-именем.

## Сборка на полностью чистой Windows

В комплект включён `BUILD_ON_CLEAN_WINDOWS.bat`. Он автоматически разворачивает портативные JDK 17 и Android SDK/NDK, переносит рабочую копию проекта в ASCII-путь и собирает debug APK без установки Android Studio. Подробности — в `WINDOWS_BUILD_README_RU.txt`.

### SOURCE_SHA256SUMS staging

В 1.2.4 Windows bootstrap принимает стандартные строки `SHA256  relative/path` и старый вариант `SHA256  ./relative/path`; скрытые пути `.github`/`.gitignore` поддерживаются. Проверка абсолютных путей и `..` остаётся включённой.
