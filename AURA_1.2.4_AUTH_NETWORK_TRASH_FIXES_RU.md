# Aura Files 1.2.4 — OAuth/network/trash fixes

## Яндекс.Диск
- Device-code OAuth остаётся официальным flow Яндекс ID.
- `/device/code` теперь идёт через глобальный официальный host `oauth.yandex.com`; при транспортном сбое используется `oauth.yandex.ru` как fallback.
- Для `/token` и refresh Aura передаёт `client_id:client_secret` через HTTP Basic Authorization, как допускает документация Яндекса. Secret больше не попадает в form-body, а `Authorization` редактируется в диагностическом `toString()`.
- Одиночная NETWORK/SERVER ошибка во время polling больше не отменяет весь OAuth flow: Aura остаётся на экране кода и повторяет запрос до истечения device-code.
- При транспортной ошибке показывается реальная причина: DNS / timeout / TLS / IOException и host, на котором закончились попытки.
- Для 5xx OAuth transport один раз пробует второй официальный Yandex OAuth host; 4xx OAuth/account ошибки не скрываются fallback'ом.
- После ошибки поле Client Secret намеренно остаётся визуально пустым, но кнопка входа повторно использует сохранённый в Android Keystore Secret.

## Google Drive
- `UNREGISTERED_ON_API_CONSOLE` распознаётся отдельно, даже если Google Play services возвращает общий status code 8.
- В сообщении выводятся package установленного приложения и SHA-1 его фактической подписи.
- В диалоге ошибки есть переход к Google Cloud Credentials и копирование полного диагностического текста.
- Aura не маскирует ошибку двумя Local-панелями: без настоящего access token и успешного Drive `about()` профиль не считается подключённым.
- Сверено с TeamAmaze/LaputaCloudsLib: их рабочая non-FOSS реализация также зависит от Google Play Services/Android OAuth registration. Их FOSS WebView OAuth не является законченным современным Android-решением, поэтому в Aura он не переносился.
- `BUILD_ON_CLEAN_WINDOWS.bat` теперь заранее создаёт/переиспользует стандартный `%USERPROFILE%\.android\debug.keystore`, печатает package+SHA-1 и пишет `BUILD_OUTPUT\GOOGLE_OAUTH_SETUP.txt`. Ключ живёт вне source ZIP, поэтому чистые распаковки на том же Windows-профиле сохраняют один SHA-1.
- `SHOW_GOOGLE_OAUTH_SHA1.bat` умеет создать этот debug key до сборки и показать SHA-1 для Google Cloud.

## Корзина Aura
- Корзина использует базовые компоненты файлового браузера: список/плитка, сортировка, поиск, штатные иконки/миниатюры и открытие файлов.
- Долгое нажатие на корневой удалённый объект включает выделение.
- Нижняя панель действий:
  - без выделения: `Выбрать` / `Очистить`;
  - при выделении: `Восстановить (N)` / `Удалить`;
  - внутри удалённой папки: `Восстановить` / `Удалить` для исходного удалённого объекта.
- Удалённые папки можно обходить как дерево, файлы — открывать штатными viewer/reader/archive механизмами Aura.
- Внутренняя `.AuraTrash` больше не показывается в обычном файловом списке Aura даже при включённом показе скрытых файлов: работать с ней нужно через раздел «Корзина».

## Сеть / облака
- «Облако» остаётся отдельным 4-м пунктом в разделе «Сеть» после LAN, «Подключиться к» и «Создать сервер».
- Обычное открытие облака — однопанельное; dual-pane остаётся отдельным режимом переноса между backend'ами.
## Windows build / SOURCE_SHA256SUMS

- Исправлен конфликт генератора и staging-парсера manifest: генератор пишет `SHA256  path`, а старый parser требовал только `SHA256  ./path`.
- Теперь принимаются оба корректных относительных формата, включая `.github/...` и `.gitignore`.
- Абсолютные пути и `..` по-прежнему блокируются.
- Ошибка `Invalid SOURCE_SHA256SUMS.txt line: ... .github/workflows/android.yml` устранена.
